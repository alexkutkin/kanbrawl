# Kanbrawl UX/UI — список задач

**Контекст.** Основные пользователи — агенты через MCP: они читают, создают, двигают и правят задачи. Веб-UI — пульт наблюдения и редкого вмешательства человека. Поэтому приоритеты смещены: сначала контракт данных, свежесть и наблюдаемость; удобство ручного редактирования — ниже.

**Легенда.** P0 — доверие и контракт, P1 — важное, P2 — полировка, P3 — позже. S/M/L — примерный размер.

**MCP-часть уточнена отдельно.** См. `kanbrawl-mcp-tasks.md`: KB-MCP-04 заменяет KB-UX-04, KB-MCP-10 расширяет KB-UX-11.

## Этап 1 — контракт и наблюдаемость

### [x] KB-UX-01 — Стабильный ID колонки и корректные rename/remove (P0, L)

**Проблема.** Имя колонки — её идентификатор. `store.updateColumns` трактует любое исчезнувшее имя как удаление и переносит задачи в `unique[0]` (`src/server/store.ts:242`). В изолированном тесте `In Progress → Doing` отправил задачу B в `Todo`, удаление `Done` отправило C в `Todo`. Клиент после `columns_updated` обновляет только колонки, поэтому задачи со старыми именами исчезают до перезагрузки.

**Что сделать.**
- Добавить `id` в `Column`; мигрировать старый `kanbrawl.json`, назначив id существующим колонкам.
- Хранить в задаче `columnId` (или обновлять `column` при rename); MCP-контракт по именам сохранить на границе.
- `updateColumns` сравнивать по `id`: rename меняет только label; remove требует destination; изменённые задачи отдавать событиями.
- В UI при rename показывать предупреждение: агенты могут ссылаться на имя колонки.

**Готово, когда.** Rename любой колонки сохраняет задачи в ней; remove переносит задачи в выбранную колонку; задачи не исчезают без reload; есть тесты store/api.

**Файлы.** `src/server/store.ts`, `src/server/api.ts`, `src/client/src/components/column-settings.ts`, `src/client/src/app.ts`.

**Источник.** Целостность данных; в Trello/Jira identity и label разделены (prior art, inferred).

### [x] KB-UX-02 — Перезапрашивать доску после `columns_updated` (P0, S)

**Проблема.** Событие содержит только колонки. Задачи, переехавшие на сервере, не приходят, и UI фильтрует их по старым именам — карточки пропадают до reload (`src/client/src/app.ts:687`).

**Что сделать.** На `columns_updated` вызывать `loadBoard()` или включать обновлённые задачи в событие. Это быстрый guard даже после KB-UX-01.

**Готово, когда.** После сохранения колонок состав задач на доске совпадает с `kanbrawl.json` без reload.

**Файлы.** `src/client/src/app.ts`.

### [x] KB-UX-03 — Живое состояние и свежесть данных (P0, M)

**Проблема.** `connected=false` при старте даёт красную пульсирующую точку `Reconnecting...` ещё до первого SSE (`src/client/src/app.ts:20`). Текста нет, `aria-live` нет. При блокировке `EventSource` доска с 7 задачами уже загружена, но точка красная. Error bar не объявляется скринридеру.

**Что сделать.**
- Состояния `connecting | online | offline`; для `connecting` — нейтральный цвет, не красный.
- Текст/иконка состояния + `role="status"`.
- Баннер «данные могут быть устаревшими» после N секунд offline; время последней синхронизации.
- Error bar: `role="alert"`, retry, очистка при успешной мутации.

**Готово, когда.** Нет ложного красного на первом экране; скринридер слышит смену состояния; при обрыве видно, что данные могут быть устаревшими.

**Файлы.** `src/client/src/app.ts`.

**Источник.** NN/g #1; WCAG 4.1.3.

### [x] KB-UX-04 — MCP: `get_task` и выборка по всем колонкам (P0, M)

**Проблема.** Агент знает id, но не может получить задачу по id. `list_tasks` по умолчанию смотрит первую колонку и отдаёт 10 задач; чтобы найти задачу, нужно обойти все колонки.

**Что сделать.**
- Добавить `get_task(id)`.
- Разрешить `list_tasks` без колонки (все колонки) или с `column: "*"`.
- Сохранить фильтры `priority`/`assignee`/`max`.
- Добавить тесты на оба сценария.

**Готово, когда.** Агент получает задачу по id одним вызовом и может перечислить все задачи доски одним запросом.

**Файлы.** `src/server/tools.ts`, `src/server/tools.test.ts`.

**Источник.** Agent-first сценарий (inferred).

## Этап 2 — редкое вмешательство и читаемость

### [x] KB-UX-05 — ID задачи, копирование и deep link (P1, M)

**Проблема.** ID нет в UI; диалог не переживает refresh; человеку нечего дать агенту, кроме заголовка.

**Что сделать.**
- Показывать короткий ID в детали и кнопку копирования.
- Маршрут `#task/<id>` с history/back; при загрузке открывать задачу по hash.
- Если задача удалена — закрыть деталь и показать notice.

**Готово, когда.** ID копируется; ссылка открывает ту же задачу после refresh; back/forward работают.

**Файлы.** `src/client/src/app.ts`.

**Источник.** Координация человек-агент (inferred).

### [x] KB-UX-06 — Подтверждение удаления задачи и колонки (P1, S)

**Проблема.** `✕` сразу отправляет DELETE; удаление необратимо. Удаление колонки молча переносит задачи.

**Что сделать.**
- Confirm с заголовком задачи (native `<dialog>`).
- Для колонки — count задач и выбор destination.
- Опционально undo-toast для задачи.

**Готово, когда.** Случайный клик не удаляет; при удалении колонки видно, куда переедут задачи.

**Файлы.** `src/client/src/components/task.ts`, `src/client/src/components/column-settings.ts`, `src/client/src/app.ts`.

**Источник.** Trello требует подтверждение для permanent delete; NN/g #5/#3.

### [x] KB-UX-07 — Одна поверхность вмешательства: карточка read-only, действия в детали (P1, M)

**Проблема.** Действия появляются только по hover; фокус на кнопке оставляет группу с `opacity: 0` (`src/client/src/components/task.ts:148`). Inline edit и read-only detail конкурируют. Drag — единственный способ перемещения.

**Что сделать.**
- Карточка: read-only, фокусируемая (button/link), Enter/Space открывает деталь.
- Деталь: read-only по умолчанию + Edit / Move to / Delete; `select` колонки.
- Убрать hover-only `✎/✕` и inline edit или оставить один явный shortcut.
- Добавить `:focus-visible` для кнопок.

**Готово, когда.** С клавиатуры можно открыть задачу, прочитать и переместить без drag; действия видимы при фокусе; на мобильном есть Move to.

**Файлы.** `src/client/src/components/task.ts`, `src/client/src/components/column.ts`, `src/client/src/app.ts`.

**Источник.** WCAG 2.1.1; WCAG 2.5.7 (канбан-доска как пример); APG Dialog.

### [x] KB-UX-08 — Не терять ввод при ошибке мутации (P1, M)

**Проблема.** `submitTask` закрывает форму до ответа сервера (`src/client/src/components/column.ts:492`), `saveEdit` сразу выходит из режима (`src/client/src/components/task.ts:342`). При ошибке введённый текст потерян. Error bar общий, без привязки к полю, без retry и без очистки после успеха.

**Что сделать.**
- Pending state; форма остаётся открытой до success.
- Inline-ошибка у поля; `role="alert"`; retry.
- Очищать ошибку при успешной мутации; не сбрасывать поля.

**Готово, когда.** Ошибка сети или валидации не уничтожает введённый текст; пользователь видит, какое поле исправить.

**Файлы.** `src/client/src/components/column.ts`, `src/client/src/components/task.ts`, `src/client/src/app.ts`.

**Источник.** WCAG 3.3.1; NN/g #9.

### [x] KB-UX-09 — Контраст и читаемость (P1, S)

**Проблема.** Тёмная тема: `--text-dimmed` 4.02:1, placeholder 3.71, `No tasks` 3.48, счётчик 3.87, P2 3.44; белый на `#ff6b35` 2.84:1 (Add/Save). Светлая тема: muted 3.40, dimmed 2.35, P2 4.40. Метаданные 10px.

**Что сделать.**
- Поднять текстовые пары до 4.5:1.
- Тёмный текст на оранжевом (6.56:1) или затемнить accent для белого текста.
- dimmed до ~`#8585a6`; light dimmed до ~`#6f6d78`; метаданные 11–12px.
- Проверить hover/disabled и обе темы.

**Готово, когда.** Все текстовые пары >=4.5:1 (large text >=3:1), включая светлую тему; кнопки Add/Save читаемы.

**Файлы.** `src/client/src/app.ts`, `src/client/src/components/task.ts`, `src/client/src/components/column.ts`, `src/client/src/components/column-settings.ts`.

**Источник.** WCAG 1.4.3.

## Этап 3 — полировка

### [x] KB-UX-10 — Наблюдаемость: кто изменил задачу (P2, L)

**Проблема.** Видно только `updatedAt` и `assignee`; нет last actor/activity. При нескольких агентах непонятно, кто передвинул или изменил задачу.

**Что сделать.**
- `lastActor` или event log.
- MCP принимает actor/assignee; SSE отдаёт actor.
- В детали — «последнее действие», без раздувания карточки.

**Готово, когда.** Человек видит, кто и когда последний раз менял задачу.

**Файлы.** `src/server/types.ts`, `src/server/store.ts`, `src/server/tools.ts`, `src/client/src/app.ts`.

**Источник.** Agent-first observability (inferred).

### [x] KB-UX-11 — Конкурентные обновления агентов (P2, M)

**Проблема.** Last-write-wins: два агента могут перетереть поля друг друга.

**Что сделать.**
- Optional `expectedUpdatedAt`/version в update/move.
- 409 при конфликте и актуальная задача в ответе.
- Не ломать старые вызовы.

**Готово, когда.** Конфликт возвращает понятную ошибку, а не молчаливое перезаписывание.

**Файлы.** `src/server/tools.ts`, `src/server/store.ts`.

**Источник.** Agent-first concurrency (inferred).

### [x] KB-UX-12 — Индикатор «зависшей» задачи (P2, S)

**Проблема.** Человек не видит, что задача давно не двигалась.

**Что сделать.** Мягкий stale-индикатор по `updatedAt` (например, >24 ч в In Progress/Blocked), tooltip с временем; данные не менять.

**Готово, когда.** Застарелые задачи заметны, но не мешают читать доску.

**Файлы.** `src/client/src/components/task.ts`, `src/client/src/app.ts`.

**Источник.** Agent-first monitoring (inferred).

### [x] KB-UX-13 — Доступность модалки настроек колонок (P2, S)

**Проблема.** Кастомный overlay: `role`/`aria-modal` нет, фокус остаётся на gear, Esc не закрывает (проверено), кнопки перемещения 18×10.

**Что сделать.**
- Native `<dialog>` или APG focus trap.
- Initial focus, Esc, `aria-labelledby`, `aria-modal`.
- Кнопки >=24×24; Enter не должен сохранять из `select`.

**Готово, когда.** Esc закрывает сразу; фокус не уходит за модалку; кнопки >=24×24.

**Файлы.** `src/client/src/components/column-settings.ts`.

**Источник.** APG Dialog; WCAG 2.5.8.

### [x] KB-UX-14 — Размер детали по контенту (P2, S)

**Проблема.** 1360×1102 для задачи на 677 символов; большая часть окна пустая.

**Что сделать.** `height: auto; max-height: 88dvh`; ширина ~1200px; строка ~90ch; длинный контент прокручивается.

**Готово, когда.** Короткая задача не открывается на пол-экрана; длинная прокручивается.

**Файлы.** `src/client/src/app.ts`.

**Источник.** NN/g #8.

## Этап 4 — позже / по потребности

### [x] KB-UX-15 — Безопасный Markdown в детали (P3, M)

**Проблема.** Сырой текст; агентские описания содержат списки и код.

**Что сделать.** Безопасный subset: списки, code, links, bold; санитайзер; карточка остаётся plain; HTML/raw не включать.

**Готово, когда.** Списки и код читаемы; XSS невозможен; карточка не раздувается.

**Файлы.** `src/client/src/app.ts`.

**Источник.** Trello/GitHub Markdown (prior art); OWASP XSS (inferred).

### [x] KB-UX-16 — Same-column drag (P3, S)

**Проблема.** Карточка тащится, но drop в той же колонке молча игнорируется; порядок задаёт сортировка.

**Что сделать.** Подсказка/курсор или убрать ложную affordance. Manual reorder не добавлять без требования.

**Готово, когда.** Нет «немого» drop.

**Файлы.** `src/client/src/components/column.ts`.

**Источник.** NN/g #1/#6.

### [x] KB-UX-17 — Широкий экран и мобильный путь (P3, S)

**Проблема.** 4 колонки по 380px с левым выравниванием оставляют большую пустую зону на 4K; mobile drag без autoscroll.

**Что сделать.**
- Центрировать доску или разрешить колонкам расти до ~480px.
- Move to в детали закрывает мобильный сценарий.
- Autoscroll — только если drag остаётся основным.

**Готово, когда.** На 4K доска выглядит цельно; на телефоне можно переместить без drag.

**Файлы.** `src/client/src/components/board.ts`, `src/client/src/app.ts`.

### [ ] KB-UX-18 — Фильтр по исполнителю/поиск при росте (P3, M)

> Отложено по собственному условию задачи: добавлять только при >30 задач в колонке или >2 агентах.

**Проблема.** Фильтров нет; при большом объёме человек не найдёт задачу.

**Что сделать.** Не добавлять сейчас. Триггер — >30 задач в колонке или >2 агентов. Тогда фильтр по assignee/priority и текст; состояние в URL.

**Готово, когда.** Фильтр не мешает основной доске.

**Файлы.** `src/client/src/app.ts`, `src/client/src/components/board.ts`.

### [x] KB-UX-19 — Reduced motion и шрифты (P3, S)

**Проблема.** `prefers-reduced-motion` учитывается только для dialog; slideIn/pulse игнорируют. Google Fonts — внешняя зависимость для LAN/offline.

**Что сделать.** Уважать reduced motion; self-host DM Sans/Space Mono.

**Готово, когда.** Нет анимаций при reduced motion; offline/LAN сохраняет типографику.

**Файлы.** `src/client/index.html`, `src/client/src/components/task.ts`, `src/client/src/app.ts`.

## Не делать сейчас

- Полноценный редактор в детали (достаточно read-only + Edit/Move/Delete).
- Rich Markdown / WYSIWYG.
- Presence и курсоры.
- Полный keyboard drag-and-drop (достаточно Move to).
- WIP-лимиты, комментарии, labels, due dates, archive, multi-board, auth.
- Bulk-операции.

Причина: минимализм и agent-first. Добавлять только под конкретное требование.

- Для серверных изменений — тесты в `src/server/*.test.ts`.

- UI проверять во встроенном браузере: rename колонки, блокировка SSE, клавиатурный сценарий, ошибка сети при создании/редактировании.
